# 🎮 SYNCRIG 서비스 개선 — 쉬운 설명서

> 이 문서는 SYNCRIG에 적용된 보안 강화 및 UX 개선 사항들을 비유와 함께 쉽게 설명합니다.

---

## 🔒 1. JWT 보안 + Refresh Token 시스템

### 비유: 카페 출입증

원래 SYNCRIG의 로그인 시스템은 **모든 손님에게 같은 비밀번호("syncrig_secret_key...")가 적힌 출입증을 발급**하는 카페와 같았습니다. 이 비밀번호가 코드에 그대로 적혀 있었기 때문에, 코드를 본 사람이면 누구나 가짜 출입증을 만들 수 있었습니다.

### 뭘 바꿨나

**🔑 출입증 발급 시스템을 완전히 개편했습니다.**

**① 비밀번호를 금고에 넣었습니다**
- 이전: 코드 안에 `'syncrig_secret_key_129847129487'`이라는 비밀번호가 그대로 적혀 있었음
- 이후: 비밀번호를 **환경변수**(서버 금고)에 보관. 코드에는 비밀번호가 없음. 만약 금고에 비밀번호를 안 넣어두면 "경고! 비밀번호를 설정하세요!"라는 알림이 뜸

**② 출입증을 두 개로 나눴습니다 — Access Token + Refresh Token**
- **Access Token** (15분짜리 단기 출입증): 카페 안에서 음료 주문, 자리 이동 등에 사용. 15분 지나면 만료됨
- **Refresh Token** (7일짜리 재발급권): Access Token이 만료되면 이 재발급권으로 새 출입증을 받음. 7일 동안 유효

**③ 출입증 자동 갱신**
- 15분 출입증이 만료되면, 사용자가 모르는 사이에 백그라운드에서 자동으로 새 출입증을 받아옴
- 여러 요청이 동시에 만료되어도 혼란 없이 한 번만 갱신 → 모든 대기 요청을 순차 처리 (카페 입구에서 줄 서서 한 명씩 새 출입증 발급받는 것)

### 실제 달라진 점
| 항목 | 이전 | 이후 |
|:---|:---|:---|
| 비밀 키 보관 | 코드에 그대로 노출 | 서버 환경변수(금고)에 보관 |
| 로그인 유지 | 1시간 후 강제 로그아웃 | 7일간 자동 갱신 |
| 보안 수준 | 누구나 위조 가능 | 서버 관리자만 키를 알 수 있음 |

### 관련 파일
- `authController.js` — 토큰 발급 로직
- `authMiddleware.js` — 토큰 검증 로직
- `authRoutes.js` — 갱신 요청 라우트
- `apiClient.js` — 클라이언트 자동 갱신

## 💾 2. 데이터베이스 경고 + 프로덕션 가드

### 비유: 화이트보드 vs. 노트북

원래 SYNCRIG의 데이터 저장 방식은 **회의실 화이트보드에 중요한 내용을 적는 것**과 같았습니다. 서버가 재시작(퇴근)하면 화이트보드가 깨끗이 지워져서 다음 날 출근하면 모든 내용이 사라졌습니다.

### 뭘 바꿨나

**📋 "화이트보드에 적고 있습니다!" 경고 시스템을 추가했습니다.**

- 서버가 시작할 때 데이터베이스 연결이 없으면:
  - `⚠️ 인메모리 DB로 동작합니다 — 서버 재시작 시 모든 데이터가 삭제됩니다!` 경고 출력
  - 실제 서비스(프로덕션)로 돌리고 있다면: `🚨 프로덕션 환경에서 인메모리 DB 사용은 위험합니다!` 강력 경고 추가
- `.env.example` 파일을 만들어 "이 환경변수들을 설정해야 합니다"라는 **설정 가이드**를 제공

### 실제 달라진 점
| 항목 | 이전 | 이후 |
|:---|:---|:---|
| DB 미설정 시 | 조용히 인메모리로 동작 | 경고 메시지 3단계 출력 |
| 프로덕션 배포 | 아무 경고 없이 데이터 소실 | 강력 에러 메시지로 즉시 인지 가능 |
| 환경변수 안내 | 없음 | `.env.example` 템플릿 제공 |

## 🎨 3. 라이트 모드 — 제대로 된 테마 시스템

### 비유: 반전 필름 vs. 양면 인쇄

원래 SYNCRIG의 라이트 모드는 **사진 필름을 반전 현상하는 것**과 같았습니다. `filter: invert(1)`이라는 CSS 속성으로 화면 전체의 색을 뒤집었는데, 이러면 사진(이미지)도 뒤집히고, 브랜드 파란색도 이상한 주황색이 되는 문제가 있었습니다. 이미지를 다시 한 번 뒤집어서 원래대로 보여주려 했지만, 완벽하지 않았습니다.

### 뭘 바꿨나

**🎭 반전 트릭 대신, 처음부터 두 벌의 옷을 만들었습니다.**

CSS 변수라는 개념을 도입해서, 각 색상에 이름표를 붙였습니다:
```
다크 모드:  --color-bg = 진한 남색(#0b0f19)
라이트 모드: --color-bg = 밝은 회색(#f1f5f9)
```

사이트 전체가 "배경색은 `--color-bg`를 써라"라고만 해두면, 다크/라이트 전환 시 색상값만 바뀌니까 이미지나 아이콘은 전혀 영향을 받지 않습니다.

### 실제 달라진 점
| 항목 | 이전 | 이후 |
|:---|:---|:---|
| 라이트 모드 방식 | 화면 전체를 뒤집기(`invert`) | 각 색상에 다크/라이트 두 벌 정의 |
| 이미지/아이콘 | 색이 반전되어 이상하게 보임 | 원래 색 그대로 정상 표시 |
| 그라디언트/차트 | 왜곡됨 | 정상 표시 |
| 정의된 색상 변수 | 없음 | 11개 (`bg`, `card`, `text`, `border` 등) |

## 🔍 4. 검색 기능 — 실제로 작동하는 검색

### 비유: 빈 돋보기 vs. 진짜 안내 데스크

원래 검색바는 **유리만 있고 렌즈가 없는 돋보기**와 같았습니다. 모양은 검색바처럼 생겼지만, 뭘 입력해도 아무 일도 일어나지 않았습니다.

### 뭘 바꿨나

**🏢 검색바가 진짜 안내 데스크가 되었습니다.**

- "대시" 또는 "통계"라고 입력하면 → **대시보드** 페이지가 검색 결과로 표시됨
- "gpu" 또는 "사양"이라고 입력하면 → **하드웨어 프로필** 페이지가 표시됨
- 검색 결과를 클릭하면 해당 페이지로 바로 이동

**키보드만으로도 사용 가능:**
- `↑ / ↓` 방향키: 검색 결과 탐색
- `Enter`: 선택한 결과로 이동
- `Esc`: 검색 닫기
- 검색창 바깥을 클릭해도 자동으로 닫힘

### 실제 달라진 점
| 항목 | 이전 | 이후 |
|:---|:---|:---|
| 검색 기능 | 없음 (장식) | 키워드 기반 실시간 필터링 |
| 결과 표시 | 없음 | 드롭다운 리스트 |
| 키보드 접근성 | 없음 | 방향키 + Enter + Esc 지원 |

## 🔔 5. 알림 시스템 — 진짜 울리는 벨

### 비유: 가짜 초인종 vs. 진짜 초인종

원래 알림 벨은 **눌러도 소리가 안 나는 가짜 초인종**이었습니다. 빨간 점은 항상 켜져 있었지만, 클릭하면 아무것도 표시되지 않았습니다.

### 뭘 바꿨나

**🛎️ 진짜 울리는 초인종으로 교체했습니다.**

- 벨을 클릭하면 **알림 패널**이 열리고, 각 알림에는:
  - 📘 정보 알림 (파란색 아이콘) — 시스템 업데이트 공지
  - 💡 팁 알림 (노란색 아이콘) — 사용 안내 및 추천
  - 🛡️ 보안 알림 (녹색 아이콘) — 보안 패치 내역
- 각 알림을 클릭하면 "읽음" 처리 → 파란 점이 사라짐
- "모두 읽음" 버튼으로 한 번에 처리 가능
- **읽지 않은 알림이 없으면 빨간 점이 자동으로 사라짐** (이전엔 항상 표시)
- `Esc` 키나 바깥 클릭으로 패널 닫기

### 실제 달라진 점
| 항목 | 이전 | 이후 |
|:---|:---|:---|
| 벨 클릭 | 아무 반응 없음 | 알림 패널 드롭다운 열림 |
| 빨간 점 | 항상 표시됨 | 읽지 않은 알림이 있을 때만 표시 |
| 알림 내용 | 없음 | 타입별 분류 + 시간 표시 |

## 👍 6. 피드백 버튼 — 진짜 눌리는 버튼

### 비유: 엘리베이터 버튼

원래 "도움됨 👍" / "작동 안함 👎" 버튼은 **눌러도 반응 없는 엘리베이터 버튼**이었습니다. 아무리 눌러도 불이 안 들어왔습니다.

### 뭘 바꿨나

**🛗 불이 들어오는 엘리베이터 버튼으로 교체했습니다.**

- **"도움됨" 버튼 클릭 시:**
  - 화면 하단에 "피드백 감사합니다! 👍" 토스트 알림 표시
  - 버튼이 초록색으로 변하고 "감사합니다!" 텍스트로 전환
  
- **"작동 안함" 버튼 클릭 시:**
  - 화면 하단에 "피드백이 반영되었습니다." 토스트 알림 표시
  - 버튼이 빨간색으로 변하고 "반영됨" 텍스트로 전환

- **중복 방지:** 한 번 버튼을 누르면 양쪽 버튼 모두 비활성화 (엘리베이터 부른 뒤 다시 못 누르는 것처럼)
- **리셋:** 모달을 닫으면 피드백 상태가 초기화되어, 다른 프로필에서 다시 피드백 가능

### 실제 달라진 점
| 항목 | 이전 | 이후 |
|:---|:---|:---|
| 버튼 클릭 | 아무 반응 없음 | 토스트 + 버튼 색상/텍스트 변경 |
| 중복 제출 | 방지 안됨 | 한 번만 제출 가능 |
| 접근성 | aria 미적용 | `aria-pressed`로 상태 전달 |

## 🚀 7. [부록] Vercel 완벽 세팅 가이드 (DB & 환경변수)

> Vercel에 배포한 뒤, 서비스가 "진짜"로 작동하게 하려면 **대시보드에서 단 두 가지**만 설정하면 됩니다.

### 🧩 1단계: JWT Secret (도장 파기)
`JWT_SECRET`은 서버가 유저에게 발급해주는 출입증(토큰)에 찍는 **"우리 가게만의 특수 도장"**입니다. 이 도장 모양을 아무도 모르게 숨겨놔야 남들이 위조 출입증을 만들지 못합니다.

1. Vercel 프로젝트 사이트 접속 → 상단 **Settings** 클릭
2. 왼쪽 메뉴에서 **Environment Variables** 클릭
3. **Key** 칸에 `JWT_SECRET` 이라고 적습니다.
4. **Value** 칸에 본인만 아는 복잡한 글자(예: `my_super_secret_syncrig_key_2026`)를 적습니다.
5. **Save** 버튼 클릭! 끝입니다.

### 🗄️ 2단계: Vercel Postgres DB 만들기 (진짜 장부 만들기)
현재 데이터베이스는 서버가 꺼지면 다 날아가는 임시 메모장(인메모리)입니다. 안 지워지는 진짜 장부를 Vercel에서 무료로 줍니다.

1. Vercel 프로젝트 상단 탭에서 **Storage** 클릭
2. **Create Database** 버튼 클릭 → **Postgres** 선택
3. 데이터베이스 이름(예: `syncrig-db`)을 적고 지역을 선택한 뒤 생성(Create)합니다.
4. 생성 창에서 뜨는 여러 옵션 중 그냥 **Connect**를 누르면, 방금 만든 DB가 현재 프로젝트에 찰칵 하고 연결됩니다.
5. **(마법 같은 일!)** 연결되는 순간, Vercel이 알아서 아까 그 **Environment Variables** 메뉴에 `DATABASE_URL`이라는 환경변수를 자동으로 쏙 넣어줍니다.
6. 이제 **Settings → Deployments**에서 점 세 개(⋮)를 눌러 **Redeploy**를 한 번 해주시면, 그 순간부터 서비스는 "안 지워지는 진짜 DB"를 사용하기 시작합니다!
